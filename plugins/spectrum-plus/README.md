# Spectrum+ Visualizer (`org.sonora.spectrum_plus`)

An advanced spectrum visualizer over Sonora's read-only audio tap. The plugin
pulls FFT magnitude bins through the capability-gated `sonora.tap_read` host
function, computes three render modes in the sandbox, and returns a descriptor
plus the latest computed frame — clients render without extra round-trips.

```
plugins/spectrum-plus/
├── manifest.json   # id, api_version, visualizer:tap only (no network)
├── plugin.wasm     # built module (checked in; rebuild with ./build.sh)
├── build.sh        # Rust -> wasm32-unknown-unknown build
├── Cargo.toml      # standalone crate (NOT a workspace member, on purpose)
├── Cargo.lock      # pinned plugin dependencies
├── src/
│   ├── lib.rs      # crate root: client always, ABI on wasm32 only
│   ├── client.rs   # pure DSP (grouping, normalization, modes, smoothing)
│   └── abi.rs      # WASM imports/exports, static memory regions
└── README.md       # this file
```

## Manifest

```json
{
  "id": "org.sonora.spectrum_plus",
  "version": "1.0.0",
  "api_version": 1,
  "capabilities": ["visualizer:tap"],
  "entry": "plugin.wasm",
  "allowed_domains": []
}
```

The plugin imports exactly `sonora.log` and `sonora.tap_read`. It declares no
other capability and performs no I/O of any kind — verify with: the host
rejects any module importing more, and this manifest has no network allow-list
to abuse.

## Capabilities

| Capability | Used for |
|---|---|
| `visualizer:tap` | `sonora.tap_read` (read-only FFT bins) + `visualizer_info` export |

Rendering stays client-side by design (see `PluginVisualizer` in the host
API): the plugin computes, the GUI/TUI draws.

## API usage

Each `visualizer_info()` call:

1. Reads up to 256 tap floats via `sonora.tap_read` (an empty tap yields a
   valid all-zero frame so clients can render silence).
2. Computes 64 bars per mode with peak normalization:
   - **bars** — log-grouped magnitudes with sqrt perceptual compression;
   - **wave** — linearly normalized downsample of the raw bins;
   - **mirror** — symmetric peak-preserving fold (`out[i] = max(bars[i], bars[63-i])`).
3. Applies release smoothing (instant attack, ×0.82 decay) against the
   previous frame kept in sandbox memory.
4. Returns JSON: `{name, modes, preferred_fps: 60, uses_audio_tap: true,
   frame: {bins, bars[64], wave[64], mirror[64]}}` (values 0.0–1.0).

Non-finite tap values (NaN/±∞/negatives) are sanitized to zero, so a corrupt
tap can never poison the output. Per-call work is O(n) over ≤256 floats with
fixed-size static buffers — no allocation, no syscalls, comfortably inside
the host fuel budget at 60 fps.

Mode selection is client-side: the response carries all three modes and the
client renders whichever the user configured. (A per-mode `visualizer_frame`
export would be the natural ABI growth if round-trips ever matter; it is
deliberately not added here.)

## Failure behavior

| Condition | Behavior |
|---|---|
| No audio / empty tap | valid zeroed frame, status 1 (renders silence) |
| Non-finite tap values | sanitized to zero, never propagated |
| `tap_read` denied | miss (status 0); cannot happen with this manifest |
| Plugin trap (bug/panic/OOM/fuel) | host marks it `Crashed`, retries with backoff, disables after 3/60 s |
| Manifest tampered (extra capability, edited id) | validation or load fails closed |

## Build instructions

Prerequisites: Rust with the `wasm32-unknown-unknown` target
(`rustup target add wasm32-unknown-unknown`).

```sh
cd plugins/spectrum-plus
./build.sh        # -> plugin.wasm
cargo test        # pure-DSP unit tests (binning, modes, smoothing), host-side
```

Host-side verification (from the workspace root):

```sh
cargo test -p sonora-plugin --test spectrum   # sandbox: tap frames, modes, gating
```

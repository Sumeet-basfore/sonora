# Sonora: v0.2 Online Enrichment Architecture, Navigation & Implementation Master Plan

## 1. Executive Summary & Strategic Objectives

Sonora v0.2 establishes the **Online Enrichment & Discovery Layer** for the Sonora desktop ecosystem. Grounded in the local-first principles of v0.1, v0.2 transforms Sonora into an artistically rich, metadata-complete music experience without sacrificing privacy, system performance, offline resilience, or clean architectural separation.

This master plan consolidates five foundational specification documents:
- `docs/23-online-metadata.md`: Online Metadata Subsystem & Provider Architecture
- `docs/24-online-search-ux.md`: Online Search Experience & Navigation Model
- `docs/25-artwork-system.md`: Unified Artwork System & Media Asset Pipeline
- `docs/26-lyrics-experience.md`: Lyrics Experience & Dedicated Manager Workspace
- `docs/27-metadata-matching.md`: Deterministic Metadata Matching & Ranking Model

## 3. Final Provider Strategy

| Domain | Canonical Primary Provider | Secondary / Fallback Providers | Authentication | Rate Limit |
| :--- | :--- | :--- | :--- | :--- |
| **Track & Release Metadata** | **MusicBrainz API (v2)** | Embedded Tags / Local SQLite | None (Public WS) | Strict 1.0 req/sec |
| **Album Cover Art** | **Cover Art Archive (CAA)** | Local Sidecar (`cover.jpg`) / Embedded ID3 | None (Public CDN) | HTTP 429 backoff |
| **Artist Visuals & Fanart** | **Wikidata / Wikimedia** | **Fanart.tv** (HD Logos/Banners) | Optional Personal Key | 100k req/week (Project) |
| **Synchronized Lyrics** | **LRCLIB Public API** | Local `.lrc` / Embedded `SYLT` / Plugins | None (Public API) | None (User-Agent req) |

### Key Guarantees
1. **Provider Abstraction**: All network logic is implemented behind Rust `async_trait` interfaces (`MetadataProvider`, `ArtworkProvider`, `LyricsProvider`). UI and audio engines never interact directly with HTTP endpoints.
2. **Zero Commercial API Paywalls**: Primary operation requires no paid API keys or subscriptions.

## 4. Final Navigation Model & UI Structure

To eliminate UI fragmentation, Sonora **rejects adding a bloated top-level "Discover" sidebar tab**.

### 4.1 Navigation Hierarchy
```
PRIMARY SIDEBAR
├── Library
│   ├── Albums
```

## 5. Implementation Roadmap & Dependency Phases

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       IMPLEMENTATION PHASE TIMELINE                         │
│                                                                             │
│  [PHASE 1: Provider Core & Matcher] ──► crates/sonora-core & provider traits │
│                                                │                            │
│                                                ▼                            │
│  [PHASE 2: SQLite Schema & Caching] ──► DB Migrations & WebP Pipeline       │
│                                                │                            │
│                                                ▼                            │
│  [PHASE 3: GUI/TUI Contextual Tools] ──► Match Inspector & Lyrics Manager   │
│                                                │                            │
│                                                ▼                            │
│  [PHASE 4: Universal Search & Polishing] ─► Unified Cmd+K Search & Testing  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Phase 1: Provider Abstraction & Matching Engine (`crates/sonora-core`)
- Implement `MetadataProvider`, `ArtworkProvider`, and `LyricsProvider` Rust traits.
- Implement MusicBrainz HTTP client with 1.0 req/sec Token Bucket rate limiter and User-Agent headers.
- Implement `DeterministicMatcher` module (Jaro-Winkler, duration penalty decay, confidence threshold classifier).

### Phase 2: Storage Migrations & Media Cache Pipeline
- Add SQLite migrations for `online_metadata_cache` and `lyrics_cache` tables.
- Implement pure-Rust WebP image decoder and thumbnail cache pipeline (`$XDG_CACHE_HOME/sonora/covers/`).
- Implement Cover Art Archive, Wikidata SPARQL, and Fanart.tv provider implementations.

### Phase 3: Dedicated UI Tools & Workspaces
- Implement **Dedicated Lyrics Manager** drawer (`Cmd/Ctrl + L`) in GUI and TUI.
- Implement **Match Inspector Modal** with side-by-side diff views.
- Implement **Artwork Candidate Inspector Modal**.

### Phase 4: Universal Global Search Integration & E2E Verification
- Integrate Online Search tabs into `Cmd/Ctrl + K` Global Search overlay.
- Execute full offline degradation and rate-limiting test suites.

## 6. Dependency Boundaries

```
[apps/desktop / apps/tui]
       │
       ▼ (Depends ONLY on Sonora Core IPC & Data Transfer Objects)
[crates/sonora-core]
       │
       ├──► [lofty / symphonia] (Local File Tag Parsing)
       ├──► [reqwest + tokio]  (Async HTTP Communications)
       ├──► [image-rs + webp]  (Zero-Trust Media Sanitization)
       └──► [rusqlite]         (SQLite WAL & FTS5 Cache)
```

- **Audio Engine Isolation**: Real-time audio playback (`sonora-audio`) has zero dependency on network providers, HTTP clients, or metadata matchers.

## 7. Risk Analysis & Mitigation Strategies

| Risk | Impact | Mitigation Strategy |
| :--- | :--- | :--- |
| **MusicBrainz IP Rate Sanction** | Online metadata lookup blocked | Enforce thread-safe Token Bucket rate limiter (1.0 req/sec) and explicit User-Agent header policy in `sonora-core`. |
| **Fanart.tv Project Key Quota Exhaustion** | Artist backgrounds fail to load | Support user-entered Personal API Key in Settings; use Wikidata SPARQL as free primary fallback. |
| **Malicious Image Decompression Bomb** | Host memory exhaustion | Enforce 64MB memory allocation cap and 8192x8192 pixel dimension guard before decoding. |
| **Low-Confidence Tag Overwrite** | User library metadata corrupted | Enforce strict rule: Never auto-overwrite tags on score < 0.90; require explicit user confirmation. |

## 8. Explicit OUT OF SCOPE Items (Anti-Bloat Boundaries)

In accordance with Sonora Product Requirements (`docs/02-product-requirements.md`) and Architectural Commitments (`docs/12-decision-log.md#adr-011-strict-anti-bloat-scope-commitments`), the following features are **EXPLICITLY OUT OF SCOPE** for v0.2:

1. **NO Audio Streaming or Downloads**: No integrations with YouTube, Spotify, Soundcloud, Bandcamp audio streams, or torrent networks. Sonora remains a local-first music player.
2. **NO Proprietary Streaming DRM Bypasses**: No decryption or ripping of Widevine/Apple Music DRM.
3. **NO Social Recommendation Feeds / Cloud Analytics**: No friend activity feeds, cloud listening scrobblers (unless user opts into Last.fm via plugin), or telemetry monitors.
4. **NO Black-Box Machine Learning Matchers**: Matching remains 100% deterministic, mathematical, and explainable.
